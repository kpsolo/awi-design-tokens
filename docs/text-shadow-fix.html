AWI Design Tokens — Solution for Text Shadow Spread Bug

Comprehensive analysis, quick workaround, and permanent Style Dictionary transform for frontend teams.

🔍 1. Root Cause Analysis (Why the Browser Drops the Shadow)

When applying --shadow-menu-banner-text-accent to CSS text-shadow in web applications, browsers mark the declaration as Invalid property value (with a warning icon in DevTools) and fail to render the shadow.

❌ What is Output (Invalid CSS)
text-shadow: 0px 0px 5px 0px rgba(92, 237, 209, 0.40);
/* 4 length values: [X] [Y] [Blur] [Spread] */
/* Browser drops entire rule: spread is forbidden! */
✔ Valid CSS text-shadow Syntax
text-shadow: 0px 0px 5px rgba(92, 237, 209, 0.40);
/* 3 length values: [X] [Y] [Blur] + [Color] */
/* W3C CSS Text Decoration Spec: valid! */
The Fundamental Conflict Between Figma & CSS:
  • CSS Specification: box-shadow accepts 4 lengths (offset-x, offset-y, blur, spread). But text-shadow strictly accepts only 2 or 3 lengths (offset-x, offset-y, blur). Providing a 4th length is a syntax violation.
  • Figma & Tokens Studio: Figma only possesses a generic DROP_SHADOW effect type, which always requires a numeric spread (even 0). When designers delete spread or pass an empty string "", Tokens Studio / Figma fails to render the effect visually on canvas layers.

⚡ 2. Immediate Quick Fix Applied to Repository

To unblock the frontend build immediately without waiting for frontend pipeline changes, the following text-shadow tokens have had their spread set to "" across all 3 brand sets (Awintura, Maggico, Twindor):

Token Name Type Updated Value Description Added
shadow.menu.banner.text-accent boxShadow spread: "" across all 3 layers Text shadow. Spread omitted for CSS text-shadow compatibility.
shadow.menu.item.text.prime boxShadow spread: "" Text shadow. Spread omitted for CSS text-shadow compatibility.
shadow.tab-bar.item.active boxShadow spread: "" Text shadow. Spread omitted for CSS text-shadow compatibility.

Output verified: Style Dictionary compiles --shadow-menu-banner-text-accent as valid 3-length CSS:

Compiled CSS Output
--shadow-menu-banner-text-accent: 0px 0px 5px rgba(92, 237, 209, 0.40), 0px 0px 8px rgba(92, 237, 209, 0.30), 0px 0px 8px rgba(92, 237, 209, 0.30);
Trade-off of this quick fix: In Figma, designers will not see the drop shadow rendered visually on canvas layers while spread is empty.

🚀 3. Permanent & Recommended Solution for Frontend Team

The architectural design token standard is to keep spread: "{depth.0}" (or 0) in Figma/Token Studio so designers have full visual fidelity, and let the Style Dictionary build transform handle CSS syntax requirements automatically.

The Frontend team should add a custom transform to their style-dictionary build script that detects text-shadow tokens and strips the 4th length parameter.

style-dictionary.config.js (or build script) 
import StyleDictionary from 'style-dictionary';
import { register } from '@tokens-studio/sd-transforms';

// 1. Register official Tokens Studio transforms
await register(StyleDictionary);

// 2. Register custom text-shadow cleaner
StyleDictionary.registerTransform({
  name: 'ts/shadow/text-shadow-clean',
  type: 'value',
  transitive: true,
  filter: (token) => {
    const isShadow = token.type === 'shadow' || token.type === 'boxShadow';
    // Match any shadow token intended for text (by token path or name)
    const isText = token.name.includes('text') || 
                   (token.path && token.path.some(p => p.toLowerCase().includes('text')));
    return isShadow && isText;
  },
  transform: (token) => {
    if (typeof token.value !== 'string') return token.value;

    // Split multiple shadow layers (comma separated, ignoring commas inside rgba/hsla)
    const layers = token.value.split(/,(?![^(]*\))/).map(s => s.trim());

    return layers.map(layer => {
      // Extract color from end of string: (lengths...) (color...)
      const colorMatch = layer.match(/^(.*?)\s+(#(?:[0-9a-fA-F]{3,8})|rgba?\([^)]+\)|hsla?\([^)]+\)|[a-zA-Z]+|var\([^)]+\))$/);
      if (!colorMatch) return layer;

      const lengthsStr = colorMatch[1].replace(/^inset\s+/i, '').trim();
      const colorStr = colorMatch[2].trim();
      const lengths = lengthsStr.split(/\s+/);

      // If 4 lengths exist (x y blur spread) -> omit spread!
      if (lengths.length === 4) {
        return `${lengths[0]} ${lengths[1]} ${lengths[2]} ${colorStr}`;
      }

      return `${lengthsStr} ${colorStr}`;
    }).join(', ');
  }
});

// 3. Add to platforms.css.transforms
const sd = new StyleDictionary({
  source: ['awi/Awi.Awintura.json'],
  preprocessors: ['tokens-studio'],
  platforms: {
    css: {
      transformGroup: 'tokens-studio',
      transforms: [
        'name/kebab',
        'ts/shadow/text-shadow-clean' // <-- Add this transform
      ],
      buildPath: 'build/css/',
      files: [
        {
          destination: 'variables.css',
          format: 'css/variables',
        },
      ],
    },
  },
});

await sd.buildAllPlatforms();
Why this solves the problem for everyone:
  1. Designers can safely restore spread: "{depth.0}" in Figma and see visual effects rendered on canvas.
  2. Frontend receives valid, error-free CSS text-shadow values in all generated stylesheets.
  3. Standard box-shadow tokens (buttons, cards, modals) retain their spread intact with zero impact.
